# KiCAD Prism on Coolify

`compose.yml` in this directory deploys KiCAD Prism as a Coolify v4
Application with the Docker Compose build pack. It pulls the digest-pinned
`v4.0.0-alpha` release images from GHCR. The Coolify server builds nothing, and
the images match the commit this fork's `main` points to.

Coolify's proxy terminates HTTPS for the `frontend` service. The frontend's
nginx proxies `/api`, `/oauth`, `/remote-provider` and
`/.well-known/kicad-remote-provider` to the backend over the stack network. No
host ports are published.

## Requirements

- A Coolify v4 server on **Linux AMD64**. Native ARM64 images are not
  published.
- At least 4 vCPU and 16 GB RAM for evaluation; 8 vCPU and 32 GB for a small
  team. See [Worker sizing](../../docs/DEPLOYMENT.md#worker-sizing).
- Enough disk for the backend image, which is several GB because it bundles
  KiCad, plus your repositories and generated artifacts.
- A DNS record, such as `prism.example.com`, pointing at the Coolify server.

## 1. Create the resource

1. In Coolify, open a project and environment and choose **Add Resource ->
   Public Repository**. The fork is public; use **Private Repository (GitHub
   App or Deploy Key)** if you make it private.
2. Repository URL: `https://github.com/TeodorSameisky/KiCAD-Prism`. Branch: the
   branch that contains this directory.
3. Build Pack: **Docker Compose**.
4. Base Directory: `/`. Docker Compose Location: `/deploy/coolify/compose.yml`.
5. Continue. Coolify reads the file and lists the five services.

## 2. Assign the domain

Under **Domains**, add a domain for the **frontend** service only:

```text
https://prism.example.com
```

The frontend listens on port 80, which is Coolify's default target port. Leave
`backend`, both workers and `postgres` without a domain. A domain on the backend
would expose the API without the frontend's proxy rules.

## 3. Set environment variables

Open **Environment Variables**. Coolify lists every `${...}` reference in the
compose file.

Required before the first deploy:

| Variable | Value |
| --- | --- |
| `PUBLIC_BASE_URL` | The exact frontend origin, `https://prism.example.com`, with no trailing slash |
| `BOOTSTRAP_ADMIN_USERS_STR` | Your administrator email |
| `BOOTSTRAP_ADMIN_PASSWORD` | A one-time password of at least 12 characters, changed at first sign-in |

Generated by Coolify. Leave these alone:

| Variable | Used as |
| --- | --- |
| `SERVICE_PASSWORD_POSTGRES` | PostgreSQL password for all services |
| `SERVICE_PASSWORD_64_SESSION` | `SESSION_SECRET` |

PostgreSQL stores its password when the volume is first initialised. Changing
`SERVICE_PASSWORD_POSTGRES` later locks the application out of its own
database.

If either generated value is empty after the first deploy, your Coolify version
did not generate it. Set both by hand to the output of
`openssl rand -hex 32`, then redeploy.

Every other variable is optional and falls back to the Prism default. The
common ones are listed in [Optional settings](#optional-settings).

## 4. Deploy

Click **Deploy**. The first deploy pulls several GB of images. Coolify waits
for PostgreSQL and the backend health checks before it starts the frontend.

Verify from any machine:

```bash
curl -fsS https://prism.example.com/healthz
curl -fsS https://prism.example.com/api/health/ready
curl -fsS https://prism.example.com/api/auth/config
curl -fsS https://prism.example.com/.well-known/kicad-remote-provider
```

`/api/health/ready` returns 503 until PostgreSQL and project storage are both
available. Every absolute URL in the last two responses must start with your
`https://` origin.

## 5. First sign-in

1. Sign in with `BOOTSTRAP_ADMIN_USERS_STR` and `BOOTSTRAP_ADMIN_PASSWORD`, then
   set a new password when Prism asks for one.
2. Clear `BOOTSTRAP_ADMIN_PASSWORD` in Coolify and redeploy. Prism never
   overwrites a real password, but the seed should not stay in the
   environment.
3. In Settings, assign roles and add a second administrator.
4. Import a small repository and run one comparison before you invite the team.

Read [Authentication and access](../../docs/AUTHENTICATION_AND_ACCESS.md) before
onboarding other people.

## Optional settings

| Variable | Purpose |
| --- | --- |
| `OIDC_ISSUER_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_PROVIDER_NAME` | Single sign-on. Register `https://prism.example.com/auth/callback` and `https://prism.example.com/oauth/oidc/callback` with the provider. Set `PASSWORD_AUTH_ENABLED=false` to make SSO the only login method. |
| `ALLOWED_USERS_STR`, `ALLOWED_DOMAINS_STR`, `DEFAULT_VIEWER_DOMAINS_STR` | Restrict who can sign in, or grant viewer access by email domain |
| `GITHUB_TOKEN`, `GITLAB_TOKEN`, `PRISM_FORGE_HOSTS` | HTTPS access to private repositories and release publishing. See [Forge hosts](../../docs/FORGE_HOSTS.md). |
| `IMPORT_ALLOWED_HOSTS_STR` | Restrict the Git hosts projects can be imported from |
| `TRACKER_CREDENTIAL_ROOT_KEY` | Required before you configure GitHub or GitLab issue trackers. Generate with `openssl rand -hex 32` and back it up. See [Tracker integration](../../docs/TRACKER_INTEGRATION.md). |
| `WORKSPACE_NAME` | Name shown on the login page |

For SSH access to private repositories, open Settings as an administrator,
copy Prism's SSH public key, install it as a read-only deploy key and pin the
host key. The key is stored in `data/ssh` and survives redeploys.

## Sizing

The defaults suit a 4 vCPU / 16 GB server. A `cpus` value above the server's
CPU count prevents the container from being created, so raise CPU limits only
on larger servers.

| Variable | Default | Notes |
| --- | --- | --- |
| `PRISM_BACKEND_CPU_LIMIT` / `PRISM_BACKEND_MEMORY_LIMIT` | `2.0` / `4g` | API |
| `PRISM_WORKER_CPU_LIMIT` / `PRISM_WORKER_MEMORY_LIMIT` | `2.0` / `8g` | Imports, comparisons, workflows, Release Studio |
| `CATALOG_WORKER_CPU_LIMIT` / `CATALOG_WORKER_MEMORY_LIMIT` | `2.0` / `4g` | Library catalog jobs |
| `UVICORN_WORKERS` | `2` | API processes |
| `PRISM_WORKER_CONCURRENCY` | `2` | Parallel general jobs |
| `CATALOG_WORKER_CONCURRENCY` | `1` | Parallel catalog jobs |

Raise one concurrency setting at a time and watch memory and job duration.
Changing a value requires a redeploy.

## Persistent state

| Location | Contents |
| --- | --- |
| Volume `prism-postgres-data` | Users, roles, sessions, projects, comments, catalog, jobs, audit records |
| `data/projects` | Git checkouts, catalog assets, generated artifacts, caches |
| `data/ssh` | Prism's Git SSH identity and known hosts |

Coolify resolves the relative `data/` paths inside the application's directory
on the server, normally `/data/coolify/applications/<uuid>/data/`. The
**Persistent Storage** tab shows the exact paths. All three items are required
to restore Prism. Back up the Coolify environment variables as well; they hold
the database password and session secret.

A logical backup, run on the Coolify server (substitute the application UUID):

```bash
cd /data/coolify/applications/<uuid>
docker exec "$(docker ps -qf name=postgres-<uuid>)" \
  pg_dump -U kicad_prism -d kicad_prism -Fc > prism-postgres.dump
tar -C data -czf prism-files.tar.gz projects ssh
```

Store both files off the server and encrypt them. They contain source
repositories, tokens and SSH private keys. `scripts/prism_backup.py` targets
the release bundle layout and has not been tested against Coolify's rendered
compose file. See [Operations](../../docs/OPERATIONS.md) for restore testing.

## Upgrades

1. Read the new release's `RELEASE_NOTES.md` and `UPGRADES.md`, and take a
   backup.
2. Copy `PRISM_BACKEND_IMAGE` and `PRISM_FRONTEND_IMAGE` from the new release
   bundle's `.env.example`. Either set them in Coolify or update the defaults
   in this file and push.
3. Redeploy.

Use the digests, not mutable tags. They are the images the release workflow
tested.

## Deploying your own code

This file deploys released images. Changes you push to the fork are not
deployed unless you build them. To build from source, replace `image:` on
`backend`, `catalog-worker` and `prism-worker` with the `build:` block from the
root `docker-compose.yml`, and on `frontend` with `build: ./frontend`. Expect
long builds: the backend compiles Rust, installs KiCad tooling and runs tests
inside the build.

## Troubleshooting

- **`range of CPUs is from 0.01 to N.00`**: a `*_CPU_LIMIT` exceeds the server's
  CPU count. Lower it.
- **Backend refuses to start with an unsafe authentication configuration**: a
  login method or `SESSION_SECRET` is incomplete. The log names the missing
  setting.
- **Sign-in loops, or provider metadata shows `http://` URLs**:
  `PUBLIC_BASE_URL` does not exactly match the domain on the frontend service.
- **Frontend returns 502**: the backend is still starting or unhealthy. Check
  the backend logs in Coolify.
- **Large library uploads fail after about 60 seconds**: Traefik v3 defaults to a
  60-second read timeout on its entrypoints. In **Servers -> Proxy**, add
  `--entrypoints.https.transport.respondingTimeouts.readTimeout=0` to the
  Traefik command and restart the proxy.
